# หลังบ้าน คลังข่าว มรส. (Node.js + PostgreSQL)

## เริ่มใช้งานในเครื่อง (ต้องเปิด Docker Desktop)
```sh
cp .env.example .env    # ครั้งแรกครั้งเดียว
npm install
npm run db:up           # เปิด PostgreSQL (พอร์ต 5433)
npm run db:migrate      # สร้าง/อัปเดตตาราง
npm run dev             # http://localhost:3000 (เปิดหน้าเว็บ + /api)
npm run db:seed         # (ไม่บังคับ) ข้อมูลตัวอย่าง: ข่าว 17 ข่าว (นำเข้าย้อนหลัง 3), ยอดอ่าน 60 วัน, งานในคิว 4 งาน — ลบด้วย npm run db:seed -- --remove
```
ล็อกอินจำลองระหว่างพัฒนา (`ALLOW_DEV_LOGIN=1`): `POST /api/auth/dev` ส่ง `{"as":"staff"}` — เลือกได้ staff, student, external, pr, admin, coordinator (ผู้ประสานงานคณะครุศาสตร์)
หน้าหลังบ้านทุกหน้ามีปุ่มล็อกอินจำลองให้กดเมื่อยังไม่ได้เข้าสู่ระบบ

`npm test` รันเทสต์ API ขณะที่ `npm run dev` ทำงานอยู่ เทสต์ลบข้อมูลที่ตัวเองสร้างทิ้งทุกครั้งหลังรัน (`test/cleanup.mjs`)

## CSS ฟอนต์ และรูปของหน้าเว็บ (build ไว้ก่อน ไม่ใช้ CDN)
หน้าเว็บไม่เรียกไฟล์จากบริการภายนอก (เร็วกว่า และไม่ส่ง IP ผู้อ่านออกไป) ทุกอย่างอยู่ใน `assets/`
| คำสั่ง | เมื่อไร | ผลลัพธ์ |
|---|---|---|
| `npm run build:css` | **ทุกครั้งที่แก้ class ของ Tailwind ในหน้า HTML/JS** หรือ `assets/src/app.css`, `tailwind.config.cjs` | `assets/app.css` และเลข `?v=` ในทุกหน้า |
| `npm run build:fonts` | เมื่อหน้าเว็บใช้ตัวอักษรที่ฟอนต์ยังไม่มี | Kanit / Noto Sans Thai เฉพาะอักษรที่ใช้ ใน `assets/fonts/` |
| `npm run build:images` | เมื่อเปลี่ยนโลโก้หรือภาพใน `brand_assets/` | โลโก้ ไอคอน ภาพ Hawky (WebP) และภาพ Open Graph ใน `assets/img/` |
ภาพข่าวย่อเป็น `.w480.webp` / `.w960.webp` ให้เองเมื่อถูกเรียกครั้งแรก (`srcset`)

## โครงสร้าง
| ไฟล์ | หน้าที่ |
|---|---|
| `index.mjs` | ตั้งค่า server เปิดเฉพาะไฟล์หน้าเว็บ (ไม่เปิด server/, uploads/, .env) |
| `auth.mjs` | ล็อกอิน Google, session cookie, ข้อมูลผู้ใช้, รูปโปรไฟล์ (`PUT/DELETE /api/me/photo`, เก็บที่ `uploads/avatars/`) |
| `db.mjs` / `migrate.mjs` | เชื่อมฐานข้อมูล / รันไฟล์ใน `migrations/` ตามลำดับ |
| `org.mjs` | อ่านรายชื่อหน่วยงานจาก `org-data.js` ชุดเดียวกับหน้าเว็บ |
| `http.mjs` | จัดการ error, กัน CSRF (ตรวจ Origin), ตัวช่วยตรวจข้อมูล |
| `news.mjs` | ฝั่งผู้อ่าน (หน้า `index.html`, `news.html`): รายการข่าว, คลังข่าว, อ่านข่าว, บันทึกข่าวที่ชอบ, ภาพข่าว `/media` (ย่อหลายขนาด) |
| `access.mjs` | ตารางสิทธิ์โมดูลหลังบ้าน (SPEC §2): `rightOf`, `requireModule` |
| `calendar.mjs` | ปฏิทินงาน: กิจกรรม การมอบหมาย ปฏิทินสาธารณะ (แจ้งเตือนอยู่ใน `notify.mjs`) |
| `phonebook.mjs` | สมุดโทรศัพท์: เบอร์โทรศัพท์และเบอร์ภายในของหน่วยงาน ค้นหาภาษาไทย นำเข้าจาก Excel/CSV |
| `requests.mjs` | คำขอใช้บริการ: เลขานุการส่งคำขอ ทีม PR อนุมัติหรือปฏิเสธ คำขอที่อนุมัติกลายเป็นงานในปฏิทิน |
| `pages.mjs` | ส่ง `news.html` / `search.html` พร้อมเนื้อหาจาก server (Open Graph, JSON-LD, ข่าวภายใน = noindex), `sitemap.xml`, `robots.txt` |
| `thai.mjs` | ตัดคำภาษาไทย (`Intl.Segmenter`) สำหรับค้นหา |
| `exif.mjs` | ลบตำแหน่ง GPS ออกจากรูปที่อัปโหลด (JPEG PNG WebP HEIC) โดยไม่บีบอัดซ้ำ — `scrub-gps.mjs` ลบจากไฟล์เก่าที่มีอยู่แล้ว |
| `backup.mjs` / `restore-test.mjs` | สำรองข้อมูลทุกคืน / ทดลองกู้คืนทุกเดือน — ดู `ops/BACKUP.md` |
| `build-css.mjs`, `build-fonts.mjs`, `build-images.mjs` | build ไฟล์ใน `assets/` (ดูด้านบน) |
| `seed.mjs` | ข่าวตัวอย่างสำหรับเครื่องพัฒนา (`npm run db:seed`) |
| `submissions.mjs` | ฝั่งผู้ส่ง: ส่งงาน (รวมส่งจากร่าง), รายการในหน้าข่าวของฉัน, ตอบข้อความ, ส่งงานที่แก้ไขแล้ว, เปิดไฟล์ — ลำดับภาพตามที่ผู้ส่งลากเรียง ภาพแรกเป็นภาพปก |
| `drafts.mjs` | ร่างที่ผู้ส่งบันทึกไว้ (ข้อความ + ไฟล์ใน `uploads/drafts/`) เห็นเฉพาะเจ้าของ ทีม PR ไม่เห็น ไม่มีเลขที่งาน สูงสุด 20 ร่างต่อคน ลบอัตโนมัติตามระยะเวลาเก็บ |
| `contact.mjs` | หน้าติดต่อเรา (`contact.html`): ทีม PR ส่วนกลาง (บทบาท pr + ผู้พัฒนาระบบ) และบุคลากรคณะที่ตำแหน่งในโปรไฟล์มีคำว่า ประชาสัมพันธ์ / สื่อสารองค์กร / PR พร้อมจำนวนข่าวที่ส่ง แสดงชื่อ ตำแหน่ง เบอร์ภายใน ไม่แสดงอีเมล |
| `pr.mjs` | ฝั่งทีม PR (หน้า `pr.html`): รายการ+ตัวนับสถานะ, เปลี่ยนสถานะ, ตอบ, เผยแพร่เป็นข่าว, จัดการทีม |
| `newsdesk.mjs` | ทีม PR จัดการข่าวที่เผยแพร่ (ข่าวเด่น, ถอนข่าว, คืนข่าว, ประวัติการแก้ไข) และนำเข้าข่าวย้อนหลัง (ตรวจข่าวซ้ำ) |
| `reports.mjs` | รายงาน/แดชบอร์ด และส่งออก Excel — ผู้ประสานงานเห็นเฉพาะหน่วยงานตน |
| `admin.mjs` | ตั้งค่าระบบ, ผู้ใช้และบทบาท, ประวัติการใช้งาน, ผลการสำรองข้อมูล (เฉพาะผู้ดูแลระบบ) |
| `settings.mjs` | ค่าตั้งต้นและการตรวจค่าตั้งค่า — หน้าเว็บอ่านผ่าน `/site-config.js` และ `/org-data.js` |
| `notify.mjs` | อีเมลแจ้งเตือน: คิวอีเมล (`email_outbox`) ส่งผ่าน SMTP ทุก 30 วินาที, สรุปงานทุกเช้า 08:00 น., การตั้งค่าของผู้ใช้ |
| `security.mjs` | CSP, HSTS (เมื่อเปิดผ่าน HTTPS) และ header ความปลอดภัย, จำกัดจำนวนคำขอ (rate limit), ตรวจชนิดไฟล์จากเนื้อไฟล์จริง |
| `privacy.mjs` | PDPA: ดาวน์โหลดข้อมูลของฉัน, คำขอลบข้อมูล, ลบบัญชีตามคำขอ, ลบไฟล์ของงานที่ไม่ได้เผยแพร่ตามระยะเวลาเก็บ |
| `audit.mjs` | บันทึกประวัติการใช้งาน (ใคร ทำอะไร เมื่อไร) ทุกการเปลี่ยนแปลงในหลังบ้าน |
| `rules.mjs` | กฎตรวจฟอร์มส่งงาน (ชุดเดียวกับ `submit.html`) และขนาด/ชนิดไฟล์ที่รับ |
| `files.mjs` | รับไฟล์อัปโหลด, ย่อภาพเป็น WebP 1600px ไว้ดูตัวอย่าง (เก็บต้นฉบับด้วย), คัดลอกภาพไปเผยแพร่ |
| `test/*.test.mjs` | เทสต์ API — รัน `npm test` ขณะที่ `npm run dev` ทำงานอยู่ |

ไฟล์อัปโหลดอยู่ใน `uploads/` — `submissions/` เปิดได้เฉพาะผู้ส่งและทีม PR, `media/` คือภาพของข่าวที่เผยแพร่แล้ว เปิดที่ `/media/...` — ข่าวสาธารณะใครก็เปิดได้, ข่าวภายในเปิดได้เฉพาะผู้ที่ล็อกอินและอยู่ในกลุ่มผู้อ่านของข่าวนั้น (ภาพขนาดเต็ม `.full.jpg` ถูกลบข้อมูล GPS/EXIF แล้ว ต้นฉบับใน `submissions/` ถูกลบเฉพาะ GPS)

ทุกการเปลี่ยนแปลงของข่าวถูกบันทึกโดย trigger ในฐานข้อมูลลง `news_revisions` (ใคร เปลี่ยนช่องไหน จากอะไรเป็นอะไร) ดูได้จากปุ่ม "ประวัติ" ใน `pr-news.html` ส่วนงานหลังบ้านอื่น ๆ อยู่ใน `audit_log` (`chanon.html#audit`)

วิดีโอรับเป็นลิงก์เท่านั้น (YouTube, Facebook, TikTok, Google Drive) — ไม่เก็บไฟล์วิดีโอบนเซิร์ฟเวอร์

## หน้าเว็บ
| หน้า | ใครใช้ |
|---|---|
| `index.html`, `news.html`, `search.html` | ผู้อ่าน — `search.html?unit=ชื่อหน่วยงาน` คือหน้าหน่วยงาน |
| `login.html` | เข้าสู่ระบบด้วย Google และกรอกสังกัดครั้งแรก — `?next=หน้า` กลับไปหน้าเดิม, `?profile=1` แก้ไขสังกัด |
| `submit.html`, `inbox.html` (ข่าวของฉัน) | บุคลากรและนักศึกษา: ส่งงาน, บันทึกร่าง, ติดตามสถานะ, ตอบ PR — `submit.html?edit=เลขที่งาน` แก้ไขงานที่ PR ขอให้แก้, `submit.html?draft=รหัสร่าง` แก้ร่างต่อ, คำนำหน้านามอยู่ใน `name-prefixes.js` |
| `pr.html`, `pr-news.html`, `pr-import.html` | ทีม PR: งานที่ส่งเข้ามา, จัดการข่าว, นำเข้าข่าวย้อนหลัง |
| `report.html` | ทีม PR และผู้ประสานงานหน่วยงาน |
| `chanon.html` | ผู้ดูแลระบบ |
| `privacy.html` | นโยบายความเป็นส่วนตัว และสิทธิของผู้ใช้ (ดาวน์โหลด / ขอลบข้อมูล) |
| `404.html`, `maintenance.html`, `status.html?s=…` | หน้าสถานะ (`s` = 404, 410, 401, 403, empty, domain, 503) |

## บทบาท
บทบาทเริ่มต้นมาจากโดเมนอีเมล: `@sru.ac.th` บุคลากร, `@student.sru.ac.th` นักศึกษา, อื่น ๆ บุคคลภายนอก
ผู้ดูแลระบบให้สิทธิ์ทีม PR, ผู้ดูแลระบบ หรือผู้ประสานงานหน่วยงาน (เห็นรายงานเฉพาะหน่วยงานตน) ได้ที่ `chanon.html` — ให้ล่วงหน้าก่อนผู้ใช้เข้าสู่ระบบครั้งแรกได้

## อีเมลแจ้งเตือน
ตั้งค่า SMTP ใน `.env` (ดู `.env.example`) ถ้ายังไม่ตั้ง อีเมลจะถูกเก็บในคิวสถานะ "ไม่ได้ส่ง" ดูได้ที่ `chanon.html#mail`
- ผู้ส่งงาน: เมื่องานเปลี่ยนสถานะ และเมื่อทีม PR ส่งข้อความ
- ทีม PR: งานใหม่ งานที่แก้ไขแล้ว ข้อความจากผู้ส่ง และสรุปงานทุกเช้า 08:00 น.
- ผู้ใช้ปิดบางประเภทได้ที่ `inbox.html#notify` (ลิงก์อยู่ท้ายอีเมลทุกฉบับ)

## ความปลอดภัย
- ทุกคำตอบมี Content-Security-Policy (สคริปต์ สไตล์ และฟอนต์จากเว็บนี้ และ Google Sign-In เท่านั้น) ส่วน HSTS ส่งเมื่อเปิดผ่าน HTTPS (ตั้ง `X-Forwarded-Proto` ที่ Nginx)
- `NODE_ENV=production`: เปิดด้วย http จะถูก redirect ไป https (`APP_ORIGIN`), แอปฟังเฉพาะ 127.0.0.1 และไม่ยอมเริ่มถ้าค่าใน `.env` ยังเป็นค่าสำหรับพัฒนา (ดู `.env.example`) ฐานข้อมูลเปิดพอร์ตเฉพาะ 127.0.0.1
- ทุก API ตรวจสิทธิ์ที่ server — `test/access.test.mjs` ไล่ทุกเส้นทาง (ไม่ล็อกอิน / บทบาทที่ไม่มีสิทธิ์ ต้องถูกปฏิเสธ) และตรวจว่าไม่มีรหัสลับในโค้ด
- หน้าเว็บมีสคริปต์ในไฟล์ HTML จึงยังต้องอนุญาต `unsafe-inline` ทุกหน้าใช้ `esc()` ก่อนใส่ข้อความลง HTML
- จำกัดจำนวนคำขอ: เข้าสู่ระบบ 30 ครั้ง / 10 นาที ต่อ IP, ส่งหรือแก้งาน 30 ครั้ง, ข้อความ 40 ครั้ง ต่อบัญชีต่อ 10 นาที, ค้นหา 120 ครั้ง / นาที ต่อ IP เกินแล้วได้ 429 พร้อม Retry-After (นับในหน่วยความจำของแอป 1 process)
- ไฟล์ที่อัปโหลดต้องมีเนื้อไฟล์ตรงกับนามสกุล (JPG PNG WEBP HEIC PDF DOC/XLS/PPT DOCX/XLSX/PPTX)
- ทดสอบ: `test/security.test.mjs` (สิทธิ์ข้ามบัญชี CSRF path traversal rate limit) และสคริปต์ XSS ในเบราว์เซอร์

## PDPA
- ผู้ใช้ดาวน์โหลดข้อมูลของตัวเองเป็น JSON และส่งคำขอลบข้อมูลได้ที่ `privacy.html#rights` ผู้ดูแลระบบดำเนินการที่ `chanon.html#requests` ภายใน 30 วัน
- ลบบัญชี: ชื่อ อีเมล สังกัด งานที่ยังไม่เผยแพร่ ไฟล์ ข่าวที่บันทึก ประวัติการอ่าน ถูกลบ ข่าวที่เผยแพร่แล้วยังอยู่โดยไม่แสดงชื่อผู้ส่ง
- ไฟล์ของงานที่ไม่ได้เผยแพร่ (ไม่เผยแพร่ / ขอแก้แล้วไม่ส่งกลับ) ถูกลบอัตโนมัติหลังไม่มีความเคลื่อนไหวตามจำนวนวันใน `chanon.html#retention` (ค่าเริ่มต้น 180 วัน) อีเมลในคิวเก็บ 180 วัน
- **ก่อนเปิดใช้:** ให้ฝ่ายกฎหมาย / เจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคลของมหาวิทยาลัยตรวจข้อความใน `privacy.html` และใส่ช่องทางติดต่อ DPO

## ยอดอ่าน
นับ 1 ครั้งต่อผู้อ่านต่อข่าวต่อวัน (ผู้ที่ล็อกอินนับตามบัญชี, คนอื่นนับจาก hash ของ IP + เบราว์เซอร์ที่เปลี่ยนทุกวัน ไม่เก็บ IP) ไม่นับบอทและตัวแสดงตัวอย่างลิงก์
ข้อมูลรายครั้ง (`news_reads`) เก็บ 90 วันแล้วลบอัตโนมัติ ยอดรวมรายวัน (`news_reads_daily`) เก็บตลอดไป
ตั้ง `READ_SALT` ใน `.env` บนเซิร์ฟเวอร์จริง เพื่อให้การนับไม่ซ้ำคงที่แม้รีสตาร์ตแอป

แก้ฐานข้อมูล: เพิ่มไฟล์ใหม่ใน `migrations/` เช่น `002_xxx.sql` — ห้ามแก้ไฟล์ที่รันไปแล้ว

## ขึ้นเซิร์ฟเวอร์มหาวิทยาลัย
ต้องการ: Linux + Docker, โดเมน (เช่น `news.sru.ac.th`) และ HTTPS ผ่าน reverse proxy (nginx) ของมหาวิทยาลัย
1. คัดลอกโปรเจกต์ไปที่เซิร์ฟเวอร์ แล้วสร้าง `.env` จาก `.env.example`
   - ตั้ง `PGPASSWORD` ใหม่ที่เดายาก, `APP_ORIGIN=https://news.sru.ac.th`, `ALLOW_DEV_LOGIN=0`, ใส่ `GOOGLE_CLIENT_ID`
2. `docker compose --profile app up -d --build` — build image ของแอป (ติดตั้งแพ็กเกจตอน build) แล้วรันฐานข้อมูล + แอป และรัน migration ให้อัตโนมัติ
   - แอปรันด้วยผู้ใช้ `node` (uid 1000) ไม่ใช่ root เขียนได้เฉพาะ `uploads/` และอ่าน `backups/` ได้อย่างเดียว
   - ถ้าตั้ง `BACKUP_DIR` นอกโฟลเดอร์โปรเจกต์ ให้แก้ volume `./backups` ใน `docker-compose.yml` ให้ชี้ไปที่เดียวกัน
   - **อัปเดตเวอร์ชัน:** `git pull` แล้ว `docker compose --profile app up -d --build`
   - **ครั้งแรกที่ย้ายจากแบบเดิม** (container รันด้วย root): `sudo chown -R 1000:1000 uploads` ก่อน `up` ไม่อย่างนั้นแอปเขียนไฟล์ใหม่ไม่ได้
3. เพิ่มผู้ดูแลคนแรก:
   ```sh
   docker compose exec db psql -U prsru -d prsru -c "insert into pr_team (email, role) values ('ชื่อ@sru.ac.th', 'admin')"
   ```
4. หน้าปิดปรับปรุง (503): ให้ Nginx แสดง `maintenance.html` เองเมื่อแอปไม่ตอบ หรือเมื่อเปิดโหมดปรับปรุง
   ```nginx
   location / {
     if (-f /srv/prsru/MAINTENANCE) { return 503; }   # touch ไฟล์นี้เพื่อเปิดโหมดปรับปรุง
     proxy_pass http://127.0.0.1:3000;
     proxy_intercept_errors on;
   }
   error_page 502 503 504 /maintenance.html;
   location = /maintenance.html { root /srv/prsru; internal; }
   location /brand_assets/ { root /srv/prsru; }        # ภาพ Hawky และโลโก้ในหน้าปรับปรุง
   ```
5. สำรองข้อมูลทุกคืน สำเนานอกเครื่อง และทดลองกู้คืนทุกเดือน: ตั้งตาม `ops/BACKUP.md` แล้วตรวจที่ `chanon.html#backups`

## Google Sign-In
Google Cloud Console → APIs & Services → Credentials → Create OAuth client ID (Web application)
- Authorized JavaScript origins: `http://localhost:3000` และโดเมนจริง
- นำ Client ID ใส่ใน `.env` (`GOOGLE_CLIENT_ID`) — ไม่ต้องใช้ Client Secret
- เมื่อมี Client ID หน้า `login.html` แสดงปุ่ม Google ของจริง (ส่งค่าให้หน้าเว็บผ่าน `/site-config.js`) ถ้ายังไม่มีและเปิด `ALLOW_DEV_LOGIN=1` จะแสดงปุ่มล็อกอินจำลองแทน
